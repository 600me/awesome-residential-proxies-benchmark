Probe protocol & sampling logic

  • Request shape: an HTTP/1.1 GET /?format=json to api.ipify.org with User-Agent: curl/8.7.1 and Connection: close, executed over a raw socket so TCP connect and the TLS handshake are timed separately from the server response.
  • Latency definition: "total" is wall-clock time from TCP connect start to the first response body byte (it includes TCP, TLS and server processing, so it is not a pure network RTT). "TLS" is time from TCP connect start to handshake completion.
  • Sampling: the project runner issues 3 concurrent requests per vendor with a 10 s total timeout, exactly as configured in config/affiliates.yaml; the standalone audit above used 5 sequential requests. Success rate is HTTP 2xx responses / requests issued for this endpoint only.
  • ASN evidence: the exit IP returned by the endpoint is looked up once per run through the free ipapi.is public interface to read ASN and hosting-vs-ISP classification. Rate limiting degrades the field to Unknown rather than fabricating a value.
  • What this does NOT measure: Cloudflare bypass ability, e-commerce or social-media success rates, throughput, or residential purity of a rotating pool. A single exit IP is one sample, not a pool audit.
